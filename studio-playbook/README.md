# 短編ゲーム縦切り制作プレイブック

20本の試作は比較候補として残し、新作の本数を増やす前に一本の操作体験を完成させる。このプレイブックは作品のルールを共通化するものではない。004「きえないで。」で実行した制作・技術QAを次の別ジャンルにも移せる形にし、感情への効果と実機品質は人による検証が済むまで未判定とする。

次の候補を始める時は [縦切り依頼書](./SLICE-BRIEF-TEMPLATE.md) を複製し、作品固有の問いを埋める。004の現行動作は [仕様書](../docs/KIENAIDE-SPEC.md)、責務は [設計書](../docs/KIENAIDE-DESIGN.md)、人の評価方法は [初見プレイテスト](../docs/KIENAIDE-PLAYTEST.md) が正本。

## 再利用するものとしないもの

| 再利用する | 作品ごとに設計し直す |
| --- | --- |
| 感情仮説を操作・結果・観察項目へ結ぶ方法 | 押す／離す、資源ゲージ、90秒という004のルール |
| 決定論的なルール、描画、音、保存を分ける考え方 | 章数、結末数、登場人物、背景、音色 |
| 両画面幅・両ブラウザ・公開版・人の評価を分けた品質ゲート | 世界観、失敗の意味、別の結末を試す理由 |

## 制作の順序

1. **問いを一つに絞る。** 誰が何を守る／失うか、プレイヤーの一操作がその状況をどう変えるか、初回10秒で何を理解してほしいかを書く。「切なさ」のような感情名だけを完成条件にしない。
2. **固有のループを試す。** 予兆、判断、入力、即時の反応、後で返る結果を一周として作る。入力の有無だけでなく、入力のタイミングや取りやめに意味を持たせる。別ジャンルでは004の長押しを流用する必要はない。
3. **場面と結末の因果を固める。** 導入、変化、山場、余韻を短い流れにする。重要な結末条件はルール・画面案内・結果説明・図鑑で一致させ、同じ入力から再現できるようにする。
4. **絵と音の基準を先に決める。** 原画の基準、人物・表情・背景・前景・光源を記録し、表示サイズで確認する。状態差分は透明レイヤーで管理し、縮小端・ノイズ・姿勢切替・音の開始と消音を実画面で見る。
5. **操作を壊さず磨く。** 小画面の主操作、距離や危険の判読、休止・復帰、キーボード、音なし、動きを減らす設定、旧保存データを検査する。ボタンの案内は実際のルール上の有利不利と矛盾させない。
6. **技術ゲートを通す。** 単体・結末・20作品回帰、390×844と360×640のChromium／WebKit、各章・分岐・全結末のスクリーンショット、音・FPS・公開版操作を確認する。PRとCIを通してmainへマージし、公開後に変更した行動を再操作する。
7. **人のゲートを別に通す。** 初見参加者が説明なしで遊び、理解時点・感情・完走・自発的な再挑戦を記録する。物理端末の音、指、通知復帰、発熱も確認する。CI成功だけで「面白い」「感情が動く」と判定しない。

## 各PRの完成条件

- 変更する体験と、変えないルールを明記する。004の仕様・設計変更は [文書更新ワークフロー](../docs/DOCUMENTATION-WORKFLOW.md) に従い同じPRで反映する。
- 再現手順、修正前の状態、修正後の期待動作、単体／実ブラウザの証拠を揃える。短い文言・飾りだけの変更を、確認済みの操作矛盾より優先しない。
- `npm run verify`、`node scripts/capture-social.mjs`、`node scripts/qa-endings.mjs`、対象作品のChromium／WebKit画面QAを実施する。失敗した検査は原因を直し、閾値を下げて緑にしない。
- PRのチェックが通った後にマージし、mainのCI・デプロイと公開URLで変更点を確認する。物理Safariと人の評価は、それぞれ別の未検証欄に残す。

## 失敗と改善の記録

修正のたびに「症状／再現条件／根本原因／変更／回帰テスト／公開結果／残る不確実性」をPRへ記す。004では、弱い灯りに一律で防御を促す案内が息切れを招いたこと、息切れ後にキーボードのフォーカスが戻らなかったことを、ルール・操作・両ブラウザのテストで修正した。これらは次作に同じ仕組みを強制する例ではなく、**案内と実際の有利な行動を照合し、操作が一時的に無効になっても復帰を検証する**ための例である。

## 現在の判定

004の技術ゲートはmainで検証済み。物理iPhone Safari、実端末の長時間安定性、初見8〜12名の感情・理解・再挑戦は未実施。次作でこの工程が通用するかも未検証のため、このプレイブックを「感情を動かす完成テンプレート」とは呼ばない。人の評価と別ジャンルでの適用結果を得た時に基準を更新し、追加量産の再開を判断する。
