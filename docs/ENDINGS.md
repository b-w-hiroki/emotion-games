# Emotion Games｜マルチエンド・収集設計 v1

## 目的

ゲーム性の芯は「ワンアイデア」。通常の目標を理解して遊べることを優先しつつ、
**意外な操作が意外な結末を生み、プレイヤーがもう一度試したくなる**構造を重ねる。

## 共通ルール

1. 1タイトルあたり最低3種類、標準5種類の結末を用意。
2. まず通常操作で最低1種類の結末へ到達できる。正解行動以外にも報酬を与える。
3. 失敗・放置・特殊入力のどれかを隠し結末として組み込む。
4. 結末はゲームごとに端末へ保存し、結末図鑑で回収率を確認できる。
5. 未回収は「？？？」＋曖昧なヒント、回収済みはタイトル・短文を表示する。
6. 新規発見は結果画面で強調し、Xに結末名とコレクト数を共有できる。
7. 秘密操作はアクセシビリティを阻害しない。主要な結末は単純操作でも取得可能にする。

## 初期3作：全15種類

| 作品 | 主軸の感情 | 通常 | 隠し / 特殊 |
| --- | --- | --- | --- |
| ぎりぎり。 | 緊張 | 普通に止める・満杯・こぼす | 放置する・一滴だけ注ぐ |
| あと1個。 | ハラハラ | 失敗・10段成功 | 積まずに待つ・次を連打・3段精密積み |
| みちゃだめ。 | 恐怖 | 最後まで耐える・途中で離す | 放置する・扉の絵を3回タップ・半分耐えて離す |

## 計測の粒度

- game_start / game_complete / game_retry
- ending_discovered（作品ID・結末ID・累計回収数）
- collection_open / share_tap（結末ID）
- Analyticsの接続は別作業。現時点では保存処理だけで外部送信は行わない。

## 追加タイトル制作契約

企画の感情 / 正規操作 / 最初の結果 / 意外な入力と結果 / 5種類の結末リスト /
UIのヒント / 収集確認 / iPhone Safari・Xアプリ内ブラウザQA / 動画の山場を1つ指定。

## Done判定

- 端末で結末発見・図鑑更新・再起動後保持を確認
- 同じ結末の再取得は二重カウントしない
- 5分以内に通常の結末を少なくとも1つ見られる
- 異常入力でJSエラー・ゲーム進行不能にならない
- 動画・画像用の結果画面がある
