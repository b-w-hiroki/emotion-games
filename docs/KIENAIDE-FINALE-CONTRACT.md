# きえないで。終盤操作・演出の実装契約

関連: #23 #29 #31。これは実装に先立つ状態・テスト契約であり、演出実装完了を意味しない。

## 状態遷移

1. `approach`: 最終章。通常の風と炎残量・呼吸残量を維持する。
2. `gust-warning`: 大突風の予兆。視覚・音・触覚（利用可能時）で知らせ、入力を受け付ける。
3. `gust-active`: 長押しで炎をかばう。かばうと炎の損失を抑え、呼吸が減る。離すと呼吸が回復し、炎が風にさらされる。入力時間を記録。
4. `silence`: 突風終了時、風音と雪の動きを短く落とす。ここでは結果を確定しない。
5. `window-reply`: 生き残った炎と記憶・選択履歴に応じて窓が反応する。プレイヤーの操作結果を光量と応答時間に反映する。
6. `ending`: 既存5結末の判定関数を単一の正本として使う。新しい演出が既存図鑑のIDを変更しない。

## 不変条件

- 90秒程度の既存ゲーム進行、5結末、図鑑と保存データを維持する。
- `flame <= 0` なら炎の表示・発光はゼロ。主人公原画の焼き込み残光は #22 で別途解消する。
- 同じ初期条件・イベント列・入力列から同じ結末に到達する。ランダム値は注入可能にする。
- `prefers-reduced-motion` では揺れ・フラッシュを抑え、情報は静的な光量・テキストでも伝える。
- 音OFF・Safari自動再生制限下でも進行を止めない。背景復帰時の二重タイマーを防ぐ。
- 導入 #31 はスキップしても `approach` 以前の通常プレイ開始状態へ遷移する。

## 受入テスト

- [ ] 予兆中に長押し開始 → 突風中の炎損失軽減と呼吸消費が計測できる
- [ ] 突風中に離す → 呼吸回復と炎リスクが計測できる
- [ ] 入力なし/かばい続ける/交互操作の3経路で結果の差が説明できる
- [ ] 突風→静寂→窓→既存結末まで遷移し、操作不能にならない
- [ ] 炎消灯時に窓の救済表現を誤表示しない
- [ ] 既存5結末・図鑑保存・リトライの回帰テスト
- [ ] 390×844、360×640、Chromium、WebKit、音OFF、reduced-motionの画面QA

## 実装順

1. 現行ゲームのタイマー・入力・結末判定を確認して上記状態を接続する。
2. イベント時刻とプレイヤー入力を記録し、決定論的テストを追加する。
3. 光・雪・カメラ・音を状態へ接続する。
4. ブラウザ動画・スクリーンショットをPRへ添付し、CI通過後にmainへ統合する。
