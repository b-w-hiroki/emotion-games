# 突風の予兆比較

## 狙いと範囲

最初の突風を見たとき、初見の人が長押しする場所とタイミングを理解できるかを確かめる。良さを認定した変更ではなく、局所的な表示の比較用。元の絵・警告文・音・押下反応を保持し、ダメージ、突風予告時間、クリア条件は変更しない。

## 比較する二版

- A: `/kienaide/?qa=1&seed=5&speed=1`
- B: `/kienaide/?qa=1&seed=5&speed=1&gustCue=anticipation`
- 技術キャプチャ時のみ `t=6.7` などで時刻を固定する。人の初見試遊では開始時刻を飛ばさない。通常速度は `speed=1` を必ず指定する（QA既定は高速）。
- 同じビルド、シード5、端末、音量、動き低減、導入既読状態で比較する。シード5の初回突風は予告6.2秒、発生7.4秒。これらの数値は変更しない。
- Bはボタン下端の細い線だけが増える。残り体力や押す長さの要求を表すゲージではない。誤解を招く場合は不採用。
- 本番の既定はAのまま。第三者のゲームやスキル本文・画像は転載しない。

## 技術ゲート

- オプトインなしでは追加要素が作られない。予告前・突風発生後・他イベント・危険状態では表示しない。
- 表示の計算はゲーム状態を変更しない。同一シード・入力のルール、ダメージ、結末、保存を保持する。
- 390×844と360×640でボタン内に収まり、ポインターを遮らない。音OFF・動き低減でも意味が残る。
- 長押し、解除、ポインター取消、休止復帰、再試行を確認。既存のverify・結末QA・画面QAも継続する。
- `node scripts/qa-kienaide-gust-cue.mjs chromium` は比較専用の確認で、既存の総合QAや実機試験の代わりではない。

## 人が判断する項目

少人数の形成的試遊では、口頭誘導なしで「何が来ると思ったか」「何をすればよいと思ったか」「失敗後、次は何を変えるか」をプレイ後に尋ねる。長押し時間ゲージとの誤認、視線の分散、文字の読みにくさがあれば改案・撤回する。

初見理解を比較するときは参加者をA先行／B先行に分け、二版目の回答を初見に数えない。匿名番号、端末、版、順序、観察、本人の回答、未回答を区別する。小標本の結果を統計的改善や「面白さ保証」にしない。正式な受入は既存の [初見プレイテスト](./KIENAIDE-PLAYTEST.md) に従う。

実装・技術確認の結果はPRに対象SHAとともに記録する。実機iPhone、初見参加者による比較、感情・納得性・再挑戦の効果は未評価。Muse等の別AIへはPR、SHA、変更範囲、検証結果、次の判断を引き継ぐが、自動読込・自動通知は未構築。
