## 2. 既にできていること

- 90秒・4章構成：雪の路地（0秒）→風のトンネル（20秒）→凍った橋（45秒）→夜明け前（70秒）。
- 操作：風の予兆を見て長押しでかばう、手を離して酸素を回復するトレードオフ。
- ゲーム状態：`flame`、`oxygen`、`wind`、`chapter`、`memoryGot`、`memories`。風力には章ごとの変化がある。
- 記憶：12/37/62秒から各8秒、3つの限定収集。取得数で到達結末が変わる。
- 結末：風で消失／かばいすぎによる酸欠／到達／記憶／完全到達。図鑑の端末保存と結果共有は共通基盤を利用。
- 絵と音：Canvas上の雪・風線・変わる空色・目的地の家・炎、Web Audio生成による風音・チャイム・低酸素時の鼓動。
- QA：`?qa=1` による12倍速経路があり、既存Playwrightで結末・収集等の動作を確認する設計。

## 4. 改善順序（量産は停止）

1. **体験台本＋入力設計**：4章それぞれの課題・前兆・プレイヤーの選択・結果・余韻をシーン単位で固定。各場面に意味のある操作と失敗原因を持たせる。
2. **縦切りのコアループ**：新しい物理/環境状態を1章に導入し、その章単体を最初から最後まで繰り返し遊べる状態にする。単なる説明追加・ゲージ追加は不可。
3. **世界観とレイヤー化した素材**：背景、主役、手、炎、風、記憶、前景、UI/結果を分割制作。色・パース・光源・状態差分の契約を持つ。
4. **演出と音の統合**：危機、守る成功、喪失、到達の操作同期を確認。
5. **実プレイ検証**：390×844、360×640、横持ち、WebKit、実機iPhone、通常速度90秒、音ON/OFF、リトライ、5結末・保存・SNS用動画。成功・未確認を別管理。
6. **制作型の抽出**：studio-playbookを共通ルールの正本とし、「感情→コアループ→状態/操作→素材→演出→QA→実プレイ→学習」を再利用できる品質基準とする。別作品に**ゲームの型そのものをコピーしない**。
