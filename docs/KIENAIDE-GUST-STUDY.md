# 突風予兆・初見比較の実施手順

## 現状調査と接続

PR #265 の f9729bc は qa + gustCue でのみB表示。QAのゲーム速度は既定12倍、導入は6倍。既存studyは experiment.js がgame_start/completeを捕捉し、任意4問・入力総数・経路等をlocalStorage emotion-games-study-v1に最大300試行保存する。回答は結末到達後のみ、途中離脱は未完走のまま残る。自動送信なし。既存集計は匿名参加者や版・順序を知らないため、そのままA/B差や実再挑戦率を計算できない。

本修正は#265上の独立した追補PR。通常ビルドには新しいbootstrapを含めない。比較用ビルドだけがQAフラグを使わず表示版・seed5・通常速度・冒頭開始を固定する。コア、ダメージ、結末、ゲームの保存処理は変更しない。

## 準備

1. 対象SHAを固定し `KIENAIDE_GUST_STUDY=1 npm run build`。GA4 ID併用はビルドエラー。通常公開用と別のローカル／アクセス制限されたプレビューで提供する。本番ホストへ置かない。noindexはアクセス制限の代わりにならない。
2. 各参加者を新規プライベートプロファイルで開始し、`/kienaide/?study=1`だけ渡す。別参加者の保存・導入既読・結末図鑑を混ぜない。本人の同意を得て端末内記録、任意回答、撤回可能なことを説明する。氏名・連絡先を収集しない。
3. 参加者には「一度遊んで、終わったら任意の質問に回答してください。続けるかは自由です」と伝える。線の意味や風の攻略を先に説明しない。
4. 同一ビルド、端末、音量、動き低減設定を維持。実機iPhone SafariとAndroid Chromeを含める。QAパラメータ、時刻飛ばし、高速化は拒否する。

## 割当と順序

cryptoによるAB/BAの独立無作為割当。小標本では人数が均等にならないため、人数と端末分布を併記する。匿名UUID・sequence・period・variant・attemptをsessionStorageへ保存し、同じタブの再読込／自由再挑戦は同じ版を保つ。タブを複製しない。

主比較はperiod1のattempt1だけ（A初見群対B初見群）。同じ人の2回目は初見に数えない。period1の自由再挑戦を観察してからJSONを保存し、観察者が「次の比較へ」を押す。period2は反対版となり導入既読のみリセットする。図鑑・攻略学習や質問による誘導は消えないため、period2は参考評価。ABとBA、period、attemptを別集計し、初見データへ混ぜない。人数不足・端末偏りを統計的改善と呼ばない。

## 記録と誤認の判定

比較JSONには既存study記録を同梱する。匿名ID、版・順序、開始時刻、最初のボタン入力までの実時間、shield/event/warningの変化とゲーム内時刻、炎・息、完走・結末・任意回答を保持。最初の入力時間は導入後のgame_start起点だが休止時間を含む。入力開始は理解の証明ではない。イベントは毎フレームでなく状態変化時のみ。途中離脱も残る。生のポインター履歴や視線は収集しない。

観察者は匿名IDと開始時刻でstudy記録と照合し、端末／音／動き低減、説明介入、最初の操作で止まった場所、休止、誤タップ、自由再挑戦の有無、離脱理由を別メモに記す。意向回答と実際の再挑戦を分離する。再読込や観察者による再開は自発的再挑戦に数えない。

結末後、先に「風が来る前、何が起きると思ったか」を回答。その後「ボタン下の線の意味」を尋ね、必要な長押し時間／風到来／体力／未認知／不明／その他を記録する。Aにも同じ質問を行い、存在しない線への回答を理解成功に数えない。自由な説明を選択肢提示前にメモすると誘導を抑えられる。誤認の発言と、線が満ちた時点で手を離す等の行動が一致するかを確認する。失敗理由の本人説明は結末ログと照合し、納得性・面白さは各1〜5の任意回答として別扱い。未回答はnull相当で、0点・誤認なしに置換しない。途中離脱者は観察メモで任意の事後回答を残す。

誤認、炎からの注意逸脱、不要な押し続け、納得性悪化があればB採用を保留し改案／撤回する。人による評価前に成功と判定しない。

## 保存と限界

結果画面の詳細→試遊記録から比較JSONを書き出す。タブを閉じる前・期を進める前に保存し、匿名ID・期・試行・回答・行動イベントがあるか確認。既存トップstudyエクスポートだけでは比較メタデータを含まない。sessionStorageはタブを閉じると失われ、既存studyはlocalStorageに残る。ブラウザ削除機能で両方を消す。自動アップロードなし。自由記述は観察メモのみ、外部共有前に同意と個人情報の有無を確認。

比較専用の集計は `node scripts/analyze-gust-study.mjs participant1.json participant2.json > summary.json` を使う。各参加者の最新エクスポートを1つだけ渡し、同じ参加者の重複入力はエラーとして扱う。初回・再試行・第2期を混ぜず、未完走と任意回答の欠測も件数として残す。集計は説明統計のみで、B採用や人の理解・楽しさを自動判定しない。既存study:analyzeは同梱studyだけを別JSONにして使う。比較集計はperiod/variant/attemptで分離し、このCLIがA/Bを分析したと扱わない。実機・初見参加者評価は未実施。PRマージ・本番デプロイは本作業の対象外。
