# Emotion Games — AIゲーム性と感情の実験プロトコル v1

## 問うこと（異なる2軸を混同しない）

1. **AI実装能力**：異なるゲームメカニクスを実際に動く実装にできるか。
   - 成果物: ルール・固有操作・状態遷移・成功失敗・隠し分岐・アセット・実ブラウザQA
   - 指標: 仕様から動作までの実装完遂率、固有の入力/物理/記憶/選択ロジック数、ブラウザ回帰率、修正回数
   - 自動テストが通っただけで「ゲーム性が面白い」とは評価しない。
2. **感情喚起**：実プレイの前後で、狙った感情が生まれるか。
   - 成果物: 主観回答と操作ログを分けた観察
   - 指標: プレイ完走率、再挑戦率、異なる結末の発見数、入力回数/時間、主観回答の内訳
   - 狙った感情が生じたかは**実際の人の回答**がなければ判定不能。AIの感想や想像は代用できない。

## 研究モードの使い方

公開した各作品のURLへ \`?study=1\` を付ける（例：\`https://play.birdman-studio.com/hikari-oikake/?study=1\`）。

- 実験モードではゲーム上の**感情ラベルを隠す**。結果前に正解を示す誘導を減らすため。
- プレイ終了後に任意の「今の気持ち」ボタンを表示。スキップして再挑戦できる。
- プレイ時間・入力回数・結末ID・スコア・回答（未回答を含む）をブラウザ内だけに保存。
- \`https://play.birdman-studio.com/?study=1\` の **JSONを保存** で手動出力、同ページで記録を削除可能。最大300件。
- 広告ID、メール、IP、GPS、ユーザーIDを保存しない。ネットワーク送信なし。
- 研究前に参加者へ、ローカル保存・任意回答・JSON提出方法を説明する。提出・公開は本人の任意。

**注意**：感情候補は簡易カテゴリなので、狙いが「期待」「高揚」「葛藤」などの場合、選択肢をそのまま一致率に換算しない。まずどの感情が多いかを見る探索的研究に限定する。正確な評価は追加の主観尺度を設計する。

## 評価実施プロトコル

1. **仮説の固定**：各作品について「押す前の予感」「操作中の葛藤」「結果」「余韻」「観察できる行動」を明記。
2. **初回プレイ**：説明なしで操作を理解できたか、誤タップ、所要秒数、完了/途中離脱を確認。
3. **1タップ感情回答**：感じた気持ちを選ぶ。回答なしも残す。
4. **再挑戦観測**：結果画面で自然に「もう一度」を選んだか、別の結末を探したか記録。
5. **混同防止**：自動テスト成功＝実装成立。面白さや感情はプレイヤー回答と行動観測が揃って初めて評価。
6. **改善**：主観と再挑戦が弱い作品は「操作→状態変化→結果」の因果を変え、絵柄の差し替えだけで改善完了にしない。

### 合否の目安（暫定、検証用で目標値ではない）

- 実装ゲート: Chrome/WebKitモバイルで主操作と固有の結末が再現。画面はみ出し・操作不能・JS例外なし。
- 体験ゲート: 参加者が何をするか理解でき、狙った感情が回答に表れるかを記録。初期10〜20件/作品は探索的レビューのみ。統計的な効果の断定をしない。
- リピート: 「収集報酬のための再挑戦」と「操作体験自体の再挑戦」を分けて質問・観察する。
- 検証モードは任意の参加者向け。X一般公開と同じUIに常時調査を押し付けない。

## 次の開発サイクル

固有の4方式を検証 → 結果を踏まえゲーム性の差を強める → 12本のテンプレートを固有メカニクスへ段階的に作り直す → 視覚・音・物理演算をジャンルに応じて選択する。コード・素材・QA・意思決定を記録して次のAI開発に再利用する。
