# 004「きえないで。」現行仕様

最終照合: 2026-10-23。正式版は `/kienaide/`。この文書はプレイヤーから見える現行動作の正本であり、過去の企画・監査ログは履歴として扱う。変更時の手順は [文書更新ワークフロー](./DOCUMENTATION-WORKFLOW.md)、実装の責務分担は [設計書](./KIENAIDE-DESIGN.md) を参照。

## 目的と範囲

縦持ちスマホで、消えかけた炎の精を雪の町の家まで運ぶ短編ゲーム。狙う感情は「守りたい」という緊張、手を離す怖さ、帰還時の安堵・喪失。感情が実際に生じるかは人によるプレイテストで評価する。20作品のうち004だけを完成縦切りとして扱い、他19作品の仕様は本書の対象外。

サイトの入口では「きえないで。」を大きく紹介し、その下のカルーセルから他の作品へ移動できる。全作品は `/works/` に並べ、チャーハンはトップページ内で遊べる。004のタイトル・導入・プレイ中の「作品一覧へ」は `/works/` に移動する。ほかの作品のデータ・保存・個別URLは維持する。入口とタイトル画面の題字は同じ筆跡の透過WebPを使い、文字情報はHTML見出しにも残す。本文・操作・結末名は可読性を優先した通常文字とする。

入口には火の子の姿を添え、導入でも少女と火の子の関係を示す。夜道では町の灯りを抑え、手元の火が少女と足元を照らす。火が弱るほど周囲も暗く感じられ、最後の窓が応答して帰還する結末では、暖かな光と広がる景色で安堵を表す。

入口には直接「旅をはじめる」と、任意の「作品を詳しく見る」を並べる。詳細はモーダルで開き、結末を明かさない紹介文、操作、約90秒の所要時間、実プレイのタイトル・雪の路地・凍った橋の画面を順に見られる。前後ボタンと左右スワイプで画像を切り替え、モーダル内からも開始できる。スクロール中も上部の閉じる操作と下部の開始操作を不透明な固定領域に残し、背後の文章を透かさない。閉じるボタンまたはEscで閉じた後は詳細を開いたボタンにフォーカスを戻す。調査モードから詳細内で始める時は `?study=1` を引き継ぐ。

共有サムネイルは1200×630の一枚絵とし、既存の少女・専用題字を雪の町の背景に重ねる。サイト入口と004の両方のOG画像に用い、生成画像内の人物や生成文字には依存しない。小さなプレビューでも炎と題字が判別できることを受入条件とする。

## プレイの流れ

1. タイトルで「旅をはじめる」を押す。第一章・最終章の背景と、その時点で必要な人物・炎・喪失の結末の絵が揃うまで開始できない。初回だけ導入の部屋の絵も開始前に読み込み、導入済みの端末では要求しない。第二・第三章の背景、橋と終盤の人物、帰還の結末の絵はプレイ中に先読みする。旧演出用の未使用素材は通常プレイでは読み込まない。必要な絵の読込に失敗した時は再読込を案内する。初回のみ約19秒の導入「最後の灯り」を表示し、いつでもスキップできる。導入済みの情報は端末に保存する。
2. 雪道を自動で進む。風の予兆を見て主ボタンを長押しすると炎をかばえるが、息が減る。手を離すと息が戻るが、強風中は炎が減る。通常の風では炎が減り始める強さから、凪ではなく長押しを案内する。灯りが弱くても凪なら手放しを案内し、息と灯りを回復させる。突風の予兆、橋の霜が濃い時、最後の風では防御を優先する。灯り・息の危険は色、点滅、文でも伝える。
3. 道中で計3回選ぶ。28秒付近の分かれ道では「吹雪の近道」か「軒先でひと息」を選ぶ。選択中は時計を止め、冷たい青の近道と暖かい琥珀の休息路を大きなボタンで示す。近道は到着を8秒早める代わりに8秒間風を強め、休息は到着を8秒遅らせる代わりに息を最大28ポイント戻し、4秒間風を遮る。息が満タンなら休息の説明は「息は満タン」とし、風よけの価値を先に示す。選択時の残距離は変わらず、以後の進み方が変わる。42秒付近の窓辺では火+14・息−18の火分けか、息+28・風よけ3秒の深呼吸を選ぶ。56秒付近の橋では火+10・風6秒強化か、息+15・風よけ3秒を選ぶ。各選択直後の物語文は短く残し、選択後も4章と終盤の操作が続く。
4. 三つの記憶は各8秒間だけ現れ、記憶の周りの光の輪が残り時間に合わせて縮む。絵の近くに出る「記憶にふれる」ボタン、絵へのタップ、Mキーで収集できる。取り逃すと短い物語文と控えめな音で知らせるが、常設表示は増やさない。同じ記憶は同一周回で二重収集できず、収集数は結末に影響する。
5. 到着前10秒に最後の風を迎える。予兆の後に大突風が5秒続き、1.5秒の静寂が来る。突風中はかばい、静寂で手を開くと窓が明るく応答する。炎が消えていると窓は暗い。炎や息が危険値でも静寂では手放す操作を先に案内し、危険の色・点滅は維持する。手を開いた後の主操作には「手をひらいている」と表示し、再び押さえるよう促さない。窓の返事中は判定が済んでいるため、主操作には到着までの案内または息を戻す案内を表示し、返事を待つ・窓に灯りを見せる操作がまだ必要だとは示さない。息の残量にかかわらず手をかざしている間は手放しを促し、すでに手を開いている場合はそのまま息を戻すよう見える案内に表示する。
6. 結末専用の絵と音、到達理由を表示する。再挑戦、結末図鑑、結末カード保存・共有ができる。音・発見済み結末は周回をまたいで残る。タイトルと結末の図鑑入口には、この端末での旅の回数と結末解放数を表示する。図鑑内では旅の開始回数と結末まで到達した回数を区別する。旅の回数はこの機能の導入後から数え、旧版のプレイを推定して加えない。

## 章と判断

| 章 | ゲーム内時刻 | 体験上の役割 |
| --- | --- | --- |
| 第一章 雪の路地 | 0–20秒 | 予兆、長押し、手を離して息を戻す基本を学ぶ |
| 第二章 風のトンネル | 20–45秒 | 渦風と凪を読み、弱風でかばう手を離すと建物の陰へ一度だけ入れる。手放したままの待機では発見しない。風よけは橋へ持ち越さない |
| 第三章 凍った橋 | 45秒〜到着20秒前 | 強風の中で手を離すと霜が蓄積し、次の強風で炎がさらに弱る。かばうと霜は和らぐが、息の消耗は増す。橋を渡ると霜は消える。近道では短く、休息路では長く渡る |
| 最終章 夜明け前 | 到着20秒前から | 二つ以上の記憶と弱い炎が窓の伏線につながり、最後の風・静寂・返事を迎える |

通常の到着は90秒、近道は82秒、休息は98秒。第一〜三章の開始時刻は共通だが、最終章は各ルートの到着20秒前（近道62秒、通常70秒、休息78秒）に始まる。近道は強風と引き換えに橋の滞在を短縮し、休息路は息と風よけを得る代わりに橋の滞在が長くなる。最後の10秒はどのルートも突風・静寂・窓の返事に使う。画面には家までの残距離、灯り、息、記憶数、残り時間を示す。字幕は一時的に出し、常時必要な操作の案内は主ボタンに集約する。

章切替では吹雪越しに背景をゆっくりつなぎ、人物と炎は透けさせない。最終章の視点移動と夜明け色は各ルートの章開始から進め、橋の絵が残る間は次章の字幕を先走らせない。

通信が遅く第二・第三章の絵、橋で使う人物、終盤の人物と帰還の結末の絵が切替時刻に揃っていない時は、旧章の絵を表示したまま旅の時計・操作・音を止め、必要な絵が揃ってから再開する。画面上部に準備中を知らせ、読込失敗なら再読込ボタンを出す。待機中は灯りや息が減らず、記憶も拾えない。残っていた記憶は再開後に拾える。

小さな風イベントは突風・渦風・ぬくい追い風・誰かの灯りが一周に各一度現れる。 渦風ではかばった後に自分で手を離すと、そのフレームから風が弱まる。ほかの強風要因がなければ、手放した瞬間に渦風のダメージを受けない。入力の中断による解除では風を弱めず、押し直して離せば隙間を作れる。突風・渦風・追い風は順番を変え、誰かの灯りは分かれ道の後に現れる。追い風中は手を離すと炎が通常より速く回復し、息も戻る。かばうとこの機会を失う。「誰かの灯り」の間は窓が風を約8割さえぎり、手を離して息を戻しても炎を守りやすい。炎への温かさも加わるが、息は通常の手放し速度で戻る。ただし吹雪の近道はその窓を通らず、選択直後の強風を受ける。近道の風が強い時は、渦風をほどいた後も主ボタンでかばうよう案内する。息が苦しい時は呼吸の回復を優先して伝える。

第二章の建物の陰を見つけた時は、短い物語文と控えめな音で知らせる。画面中央に四角い色面は重ねず、家までの距離は風よけ中も表示する。音を切っている時は通知音を鳴らさない。

第三章では霜が画面の端から濃くなり、蓄積して強風を受けている時は主ボタンが対処を促す。凪では息を戻し、強風ではかばって霜を和らげる。常設の数値ゲージは増やさない。

## 結末の優先順位

上から先に判定する。結末IDは保存データとの互換性を守るため変更しない。

| ID | 表示名 | 現行条件 |
| --- | --- | --- |
| `smother` | 守りすぎた。 | 息が0になる |
| `blown` | 風にさらわれた。 | 炎が0になる |
| `dawn` | おかえり。 | 生存して到着、記憶3個、到着時の炎68%以上、最後の窓が明るく応答 |
| `wish` | わすれない。 | 生存して到着、記憶3個、`dawn` の条件に届かない |
| `survive` | まだ、ここに。 | 生存して到着、記憶が3個未満 |

明るい返事は、大突風中のかばいが2.5秒以上、静寂中の手放しが0.45秒以上、炎が残っている時に成立する。片方だけならかすかな返事、どちらもなければ暗い窓。弱い炎が戻る別の「奇跡」は、各ルートの最終章に入ってから、記憶2個以上・炎29%以下かつ残存・息30%以上・弱風で自分から手を離すなどの条件で発生し得る。強風中に離して後から凪になっても、奇跡の手放しには数えない。画面非表示、フォーカス喪失、入力キャンセルによる強制解除も数えない。条件が揃ってかばっている時は主ボタンに手放す案内を出し、危険表示だけで逆の操作を促さない。奇跡は帰還の結末条件を置き換えない。

## 操作・休止・アクセシビリティ

- 主操作はタッチ／ポインター長押し。Space・Enterでもかばえる。炎をかばったまま別の指で「記憶にふれる」または画面上の記憶を押せる。記憶へのタッチを途中で取り消したり対象の外へ離したりした場合や、休止・画面非表示・横向き・章の画像待ちを挟んだ場合は収集しない。
- 描画更新の間に押下と手放しが続けて届いた場合も、意図した手放しとして判定する。入力キャンセルやフォーカス喪失は含めない。
- 通常時に息が少ない状態でかばっている時は、手を離す理由を息の苦しさとして伝え、風が強いままなのに「風が弱まった」と表示しない。息が危険な間はタッチ・ポインター・キーボードの新たな長押しを一時的に無効にする。無効中に押したまま回復しても自動でかばわず、離してから再度押すと操作できる。回復後はキーボードの主操作へ戻れるが、プレイヤーが別の操作へフォーカスを移した場合は奪わない。
- 休止メニュー、道の選択、図鑑、導入中はゲーム時計・ルールを止め、背面への入力を遮断する。プレイ中の短い物語・操作案内は、中断中に読み時間を消費せず、再開後に残りの時間を表示する。 画面が見えたままウィンドウのフォーカスを失った場合も、押し続けを解除して旅の時計と音を止め、フォーカスが戻ったら続きから再開する。休止メニューでは操作説明、音量／ミュート、図鑑、やり直し、タイトルへ戻るを提供する。進行を失う操作は確認を挟む。導入中もフォーカス喪失・非表示・横向きの間は時間を止め、描画更新が届かない場合も復帰時に飛ばさない。導入と結末の音は流すが、休止・道の選択・図鑑では音声も停止する。フォーカスや画面が戻った時、導入・旅・結末の音声を再開する。結末の絵と結果表示も同じ中断中は進めず、音とともに続きから再開する。ミュート設定は維持する。
- 表紙・導入・結末には作品一覧への戻るリンクを見える位置に置く。プレイ中の戻るボタンは休止確認を経て作品一覧へ戻り、進行が失われることを伝える。最初の操作案内は長押しと手放しを一続きで説明する。
- 火の子が守られるだけでなく少女を支える反応として、最終章より前に息が減った状態で凪に自分から手を離した時、一周に一度だけ息を最大6ポイント返す。強風での手放しや入力キャンセルでは起こらない。手元の暖かな光、短い字幕と操作案内で因果を伝える。
- 背景タブや短い横向き表示でも進行と音声を止め、復帰時に経過時間をまとめて進めない。復帰先が休止・道の選択・図鑑なら音声は停止したままにする。開始直後に休止した場合も、遅れて完了した音声再開で休止画面に音が流れない。音が利用できない環境でもプレイを続けられる。
- 画面読み上げ用の灯り・息メーターと危険通知を持つ。`prefers-reduced-motion` では強い動きを抑える。360×640と390×844の縦画面を回帰対象とする。

## 保存・共有・再プレイ

任意の `?study=1` では、結末後に感情・理解時点・強度・再プレイ理由の4問を端末内へ記録できる。道の選択と004の二つの判断、記憶の取得・取り逃し、火の子の返事、風よけ、奇跡、窓の応答は結末前に端末内へ保存し、途中離脱も含めて迷いの場面を見直せる。これらはイベントの発生記録であり、感情や操作理解を自動判定しない。同じ端末内の試行番号は再読込後も続けるが、人物の識別には使わない。強度の1と5には意味を添え、幅360pxの縦画面でも各回答と開閉操作は44px以上のタップ領域を持ち、スクロールして最後の回答まで届く。通常プレイには質問を表示しない。

図鑑は五つの結末IDを端末内に保存し、重複を数えない。旧版の結末データを統合する。発見が3/5なら余韻の手紙、5/5なら称号を表示する。周回中の記憶・進行は再挑戦で初期化される。共有URLからQA専用パラメーターは除く。結末カードはPNGを準備し、利用可能なら端末の共有機能、そうでなければダウンロードを使う。共有・投稿はプレイヤーの操作でのみ起動する。

公開用の終盤動画は6〜12秒・1080×1920のMP4とする。操作画面を切り取らず全体を見せ、9:16との差は同じ場面を暗くぼかした背景で埋める。最後は結末カードの準備完了後の画面と公開ゲームURLを表示し、最低2秒間は最終画面を保持して読めるようにする。処理中表示では終わらせない。動画の録画はQA用の状態指定を使うが、通常ゲームのルールを使い、プレイヤーの結果や実測データとして扱わない。
